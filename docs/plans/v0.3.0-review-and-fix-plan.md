# 0.3.0 代码审查与修复计划

日期：2026-11-10。

## 审查范围

- 当前工作区 `src/com.vibecoding.sts2mod.json` 声明版本为 0.3.0；审查包含已跟踪修改及未跟踪的前端、回合与素材构建代码。
- 审查开始时分支为 `codex/raven-lamp`，HEAD 为 `12dca65`，最近版本标签为 `v0.2.0`；0.3.0 尚未形成版本提交或标签。
- 本轮只审查、验证并制定修复计划，不修改玩法实现，不部署，不启动游戏 GUI，保留现有工作区改动。

## 审查与验收方法

1. 并行检查核心玩法/持久化、前端/原版界面衔接、资源构建/部署，复核跨模块调用链。
2. 涉及游戏行为时，使用 ILSpy MCP 核对本机 `references/sts2.dll` 的真实实现。
3. 执行锁定依赖构建、现有离线测试和隔离 headless 探针；保留本次输出。既有测试通过不等于新交互路径无缺陷。
4. 每项确认问题记录触发条件、实际后果、代码位置、修复方向及验收标准；未复现的风险单独列出。
5. 后续运行时验证只允许 `tools/verify-environment.ps1 -HeadlessGame`，并确认显示驱动为 `headless`。最终交互显示由用户手动验收。

## 结论

发现 5 项确定的代码或工具链缺陷，以及 1 项触发条件受限的候选刷新缺陷。退出交接和输入路由应优先修复。当前版本可编译、可加载，但不能据此视为交互验收通过。

下列问题以当前工作区行号定位。运行时交互结论来自代码、引擎输入规则和本机 API 调用链核对，未启动 GUI 复现。工具链问题有本次离线执行证据。

## 问题清单

### F1 · P1：退出自动领取可能在黑屏下等待原版选择

- 位置：`src/Hooks/Raven/RavenOverlayHooks.cs:121-122`；关联 `RavenRoundHooks.cs:85-88`、`Frontend/RavenStageTextHooks.cs:39-43`。
- 触发：替换结果尚未拾取，目标遗物带需要玩家选择的拾取效果，此时直接退出路灯。
- 调用链：`ExitWithTransition` 完成 FadeOut 后等待 `ExitAsync → CollectAsync → RelicCmd.Replace → Obtain → AfterObtained`，FadeIn 直到这条调用链结束后的 `finally` 才发生。
- 本机 ILSpy 证据：`NTransition.RoomFadeOut` 的遮罩不透明并拦截鼠标；`RelicCmd.Replace` 先等待 Remove 再等待 Obtain；SeaGlass 的拾取效果等待奖励选牌，PreciseScissors/EmptyCage 等待删牌选择。这些选择需要可见、可交互的原版界面。
- 后果：玩家看不到选择界面，也无法正常点击完成；退出流程可能一直挂起。普通点击领取会根据 `HasUponPickupEffect` 移开面板，退出自动领取没有复用该处理。
- 修复：统一点击领取与退出自动领取的协调流程。需要原版交互时先移开路灯并确保画面可见，再等待拾取；完成后结束机会并执行退出过场。以独立退出意图阻止中途重新打开路灯；过场和忙碌状态在成功、失败、取消路径均释放。
- 验收：用受控未完成 Task 模拟原版选择，断言等待期间遮罩已退、路灯已移开、没有重复领取或重入；选择完成后只结束一次机会。用户再手动验证普通/快速模式下选择型遗物的退出领取。

### F2 · P1：快捷键未送达，背包返回会误退出机会

- 位置：`src/Hooks/Raven/RavenLampPanelHooks.cs:34`、`:68-72`、`:90-107`；`src/Hooks/Raven/Frontend/RavenHudHooks.cs:51`。
- 触发：正常打开面板后，焦点在背包按钮、遗物格或奖励格；使用 B/F，或在背包打开时按 Esc/手柄返回。
- 原因：键盘处理只订阅根面板 `GuiInput`，焦点却交给子控件；根面板本身没有启用焦点。键盘/手柄 GUI 事件不会像鼠标事件一样向父节点冒泡，因此根面板的快捷键处理无法接到这些事件。[Godot 4.5 官方输入规则](https://docs.godotengine.org/en/4.5/tutorials/inputs/inputevent.html#how-does-it-work)
- 返回路径另经原生 `NBackButton` 全局热键触发。ILSpy 核实其 cancel/pauseAndBack/back 绑定和 `NHotkeyManager` 分发；HUD 将 Released 直接连到退出，没有先执行背包关闭。
- 后果：B/F 无法按说明工作；用户想关背包时可能直接消耗当前机会。
- 修复：建立可收到实际事件的输入路由，可使用已核实的原生热键接口或焦点控件转发；所有返回入口统一执行“背包打开则只关包，否则退出”。处理完成后消费事件，并在面板隐藏/关闭时注销或禁用。保持项目没有 Godot 源生成器的约束，不直接添加不会生效的虚方法覆写。
- 验收：通过隔离 headless 场景的 Viewport 分发按键，分别让各类子控件获得焦点，检查 B/F、Esc 和手柄返回。首次返回只关包，机会数和 revision 不变；下一次返回才退出。不能用直接调用处理方法或直接发 Pressed 信号替代输入路由测试。

### F3 · P2：0.2.x 三选一存档迁移后重复增加轮次

- 位置：`src/Hooks/Raven/RavenSessionHooks.cs:49-65`；`src/Hooks/Raven/RavenSettlementHooks.cs:27`、`:43`。
- 触发：载入含 `BonusCandidates` 的 0.2.x 存档，领取奖励，或最后一个候选被判定失效。
- 原因：0.2.x 的 SubmitAsync 生成候选时已经执行 CompleteRound。迁移只写入 `NextLights=-1`，而新版 ApplyRound 即使灯数不变也无条件 `Round++`。
- 例子：旧状态 `Round=5, Lights=3`，迁移领取后变成 `Round=6, Lights=3`，实际没有新的投放，界面轮次超前。
- 修复：为待领取结果明确记录“本轮已推进”，旧状态迁移时置为已推进。兼容已经由 0.3.0 写出的 `NextLights=-1` 待领取状态，不能只处理仍含 BonusCandidates 的存档。领取和候选耗尽共享该判定，避免再次推进轮次/灯数。
- 验收：覆盖旧存档迁移后的领取、候选耗尽、放弃、保存恢复及再次载入；前两种保持原轮次/灯数，下一次正常投放只推进一次。修正现有只验证迁移结构、未执行后续结算的测试缺口。

### F4 · P2：损坏素材会通过构建前校验

- 位置：`tools/stage-raven-assets.ps1:20-29`、`:37-49`；相关成功夹具 `tests/build-mod.Tests.ps1:52-67`。
- 离线复现：仅含尺寸头的 24 字节 PNG、30 字节 WebP，以及声明 1600 字节音频却没有数据的 44 字节 WAV，均被接受，退出码 0，并生成资源 manifest。
- 原因：图片只检查头部尺寸；WAV 信任 data 块声明长度，没有核对实际文件边界。PCK 报告只验证条目及大小，不能代替解码。
- 后果：截断/损坏素材可以进入打包和后续部署，运行时出现缺图或无音效；不符合“损坏素材构建失败且不改动安装”的要求。本轮未把损坏夹具部署到真实游戏。
- 修复：在部署之前用现有 Godot headless 工具完整解码原始图片，核对尺寸/帧格；WAV 同时验证 RIFF/chunk 边界、采样率、块对齐、字节率和实际 PCM 长度。成功夹具换成真实可解码的自生成媒体。
- 验收：截断图片主体、缺失图片数据、损坏格式、截断 WAV/data 长度越界均使构建失败；既有 Mod 安装内容哈希完全不变。合法 PNG/WebP/WAV 与含空格/中文的路径均成功。
- 证据：[复现结果](../../artifacts/verification/review-v0.3.0-20261110/asset-validation-repro-result.json)、[复现脚本](../../artifacts/verification/review-v0.3.0-20261110/asset-validation-repro.ps1)。

### F5 · P2：文档规定的构建测试入口在读取清单时失败

- 位置：`tests/build-mod.Tests.ps1:78`。
- 实测命令：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/build-mod.Tests.ps1`。
- 原因：`Get-Content -Raw` 未指定 UTF-8。Windows PowerShell 5.1 在本机使用系统 ANSI 解码无 BOM 的 UTF-8 清单，中文 description 损坏，ConvertFrom-Json 抛错。
- 后果：测试退出码 1，尚未执行后续构建、部署与回滚断言；这不是主 Mod 编译失败。
- 修复：该测试所有 JSON 读取显式指定 `-Encoding UTF8`，包括当前第 55、78、171、173、176、188 行；检查其余文本读取是否同样依赖默认编码。
- 验收：继续使用文档规定的 Windows PowerShell 5.1 完整运行，加入无 BOM 中文清单及中文路径夹具，确认真正执行到末尾 PASS，而非换 shell 绕过。
- 证据：[本次失败日志](../../artifacts/verification/review-v0.3.0-20261110/build-tests.log)。生产 build/staging 脚本相关读取已显式使用 UTF-8。

### F6 · P2（条件性）：失效候选被剔除后，奖励图标和领取索引未刷新

- 位置：`src/Hooks/Raven/Frontend/RavenStageFlowHooks.cs:57-61`；关联 `RavenSettlementHooks.cs:20-30`、`Frontend/RavenStageTextHooks.cs:40-43`。
- 触发前提：旧存档或外部状态变更使已展示的三选一候选不再满足 CanClaim，且领取走面板内结算。正常封闭流程中尚未发现自然产生该资格变化的路径。
- 原因：服务剔除候选后更新 revision 并通知 UI；EnterPickup 更新了 `_plan`，却因 `_rewardsShown=true` 保留旧槽位。此前 FlyAway 已让这些槽位淡出。
- 后果：剩余可领取奖励不可见，或显示对象、悬停提示与实际领取索引错位。
- 修复：候选内容/身份变化时重建槽位，取消旧动画并恢复可见性、交互和焦点；尽量用候选身份与 revision 关联领取请求，避免旧索引命中新候选。
- 验收：模拟首项和中间项失效，确认剩余两项的显示 ID、悬停 ID 和实际领取 ID 一致，全部失效正确进入下一轮；覆盖面板保留和临时关闭两种路径。

### 验证边界与待调查项

- 内置功能探针明确只覆盖规则、状态、序列化和节点，没有启动一局或执行实际玩法交互。现有新增回合测试没有真正走完 PlanRound/CollectAsync/ExitAsync/ResolveSwallowAsync，因此不能排除 F1/F3；节点 Pressed 信号测试也不能证明 F2 的事件路由有效。
- 本次日志在 `RavenCandleHooks` 创建 ShaderMaterial 时记录了 30 次 `custom_samplers` shader 编译诊断，仍返回探针通过；另有 SeaGlass 测试夹具未设 CharacterId 的警告，以及退出时 RID/资源释放诊断。保留[引擎日志](../../artifacts/verification/20261110-185248-760/headless/headless-engine.log)。结合上游 Godot 4.5.1 的 [Dummy 实现](https://raw.githubusercontent.com/godotengine/godot/4.5.1-stable/servers/rendering/dummy/storage/material_storage.cpp)与[正常 Canvas 实现](https://raw.githubusercontent.com/godotengine/godot/4.5.1-stable/servers/rendering/renderer_rd/renderer_canvas_render_rd.cpp)，推断这是把内置 TEXTURE 传入 sampler2D 辅助函数时触发的 Dummy 映射限制，尚未据此断言游戏 GUI 火焰异常。可将辅助函数限于计算 UV、在 fragment 内直接采样，随后验证该组诊断是否消失；真实 GPU 渲染仍待用户验收。本次不能称为“零错误运行”。
- 分辨率越界的初步怀疑已排除为确定缺陷：本机 NGame/NGlobalUi 会设置逻辑内容尺寸，不能把物理 720p 直接当成面板逻辑高度。
- README、CHANGELOG 仍描述 0.2.0；0.3.0 的实现文档结果栏未填写。属于发布记录缺口，修复验证后统一更新，不冒充独立运行时 bug。
- 状态：现有 headless 探针通过，存在待修复缺陷，待用户 GUI 验收；没有宣称最终验收通过。

## 修复实施顺序与完成标准

### 阶段 0：固定待修复基线，恢复测试入口

1. 保留并核对当前全部 0.3.0 修改及新增文件，单独形成可恢复的源码基线；不要把现有未提交工作丢弃或误归为本次修复。
2. 从该已提交基线建立 `codex/v0.3.0-fixes` 等任务分支，不移动 v0.2.0 标签。
3. 修复 F5，使 Windows PowerShell 5.1 构建部署夹具可完整执行；保存修复前后的日志。
4. 独立提交编码与夹具修复，提交说明记录实际通过范围。

### 阶段 1：修复退出交接与输入路由（F1、F2）

1. 提取最小的领取/退出协调边界，允许测试注入过场、关闭面板及异步领取委托；复用既有结算服务，不扩大到存档体系重写。
2. 统一自动领取和点击领取，修正淡入/淡出与原版选择的等待顺序；保留防重复调用与错误释放。
3. 统一快捷键和返回入口，确保背包优先关闭且事件不会继续触发原版返回。
4. 增加真实输入分发测试及受控异步选择测试，覆盖正常、快速、异常、取消、重复点击、隐藏/重开。
5. 构建与离线用例通过后提交这一阶段。未完成这两项前，不作为可交互验收版本发布。

### 阶段 2：修复兼容存档与候选刷新（F3、F6）

1. 为迁移结果增加明确的回合推进语义，同时兼容 0.2.x 与已迁移的 0.3.0 状态。
2. 调整候选集合更新后的奖励节点和领取身份绑定。
3. 执行真实迁移后领取/耗尽流程的回归，验证状态、轮次、灯数、候选和实际发奖保持一致；不修改真实存档作测试。
4. 独立提交状态与候选刷新修复。

### 阶段 3：加固资源校验（F4）

1. 把完整解码和 WAV 边界检查放在所有真实部署写入之前。
2. 替换 header-only 成功夹具；加入本次 3 种反例与既有安装哈希不变的断言。
3. 实际素材 BuildOnly、完整 PowerShell/Python 回归通过后提交。

### 阶段 4：汇总验收与发布记录

1. 重新执行 Release locked build、PCK 校验、全部离线测试和唯一允许的隔离 headless 验证。检查本次初始化记录及日志，对新增 shader/资源错误明确归因，不能只看退出码。
2. 若 headless 无法覆盖过场和原版交互，保留未验证项；禁止转用 GUI 自动化或隐藏窗口。
3. 用户手动验证：B/F/Esc/手柄返回、选择型遗物自动领取、三选一领取/放弃、动画门控、存档恢复、火焰/音效和不同图形后端。
4. 同步中英文 README、CHANGELOG 和前端计划的实施结果；保持 Mod 名称与产物身份一致。只有用户确认 GUI 后才记录最终验收通过。
5. 修复阶段各自检查暂存区后提交；正式保留版本按仓库流程使用新附注标签，不自动推送模板上游。
