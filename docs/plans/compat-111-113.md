# 同时兼容游戏 111 与 113

日期：2026-11-15。用户授权按本计划实施、验证并部署到当前游戏；禁止游戏 GUI。

## 目标与设计

- Sts2ModScaffold 0.3.1 使用同一 DLL/PCK 支持游戏 0.111.0、0.113.1，保留 net9.0、Mod ID、玩法概率、raven_lamp/schema 1 和旧存档迁移。
- 主 Mod 固定游戏 0.111.0 编译基线及 STS2.RitsuLib.Compat.0.111.0 [0.6.13] 编译专用包。两版运行时统一使用完整 RitsuLib 0.6.13，分别选择 compat/0.111.0、compat/0.113.0。
- 已用 ILSpy 核验游戏 API：现有主 Mod 的 154 个游戏成员引用只有 Rng.Shuffle 在 113 移除。以本地 descending Fisher–Yates 替代，保持输入排序及原流 NextInt 消耗；原有 Harmony 目标保留。
- STS2MCP、STS2MenuControl 同源码按目标分别编译。新兼容补丁在主仓库保存，STS2MCP 商店调用以 Sts2ApiTarget 选择 111 原入口或 113 MerchantSynchronizer；不改外部协议，不绕过购买同步。
- build/install 增加 BaselineGameDir 和本地 BASELINE_GAME_DIR；GameDir 仍表示部署目标。引用缓存、中间产物和辅助输出隔离，报告记录实际版本、API 目标、基线及哈希。仅允许已验证版本映射。
- NuGet 锁、运行时完整性、headless 探针版本与当前文档同步更新；历史验证记录不改写。

## 验收标准

1. 固定种子洗牌基准验证排列、后续随机值和 JSON 恢复续流；保留完整已有玩法和布局回归。
2. 主 DLL 的精确成员引用在 111、113 均可解析。三个 Mod 完成两版构建、依赖边界和 PCK 检查；辅助补丁可从锁定上游完整重放并重复识别。
3. 离线测试覆盖双版本映射、库版本/哈希/CRC、缺失兼容分支、未知版本拒绝、构建隔离和 GUI 禁令。
4. 用同一份哈希一致的主 Mod 产物分别调用 tools/verify-environment.ps1 -HeadlessGame。111 只读使用已保留游戏资源建立新镜像；两版均使用独立数据目录和当前工坊 0.6.13。
5. 确认实际显示驱动 headless、本次初始化日志、功能与布局检查、退出状态；保留旧日志与失败诊断，失败不得回退 GUI。
6. 辅助 Mod 只做编译/静态/离线协议检查，不进入运行时测试镜像，不调用菜单或带副作用的状态接口。
7. 两版通过后，游戏关闭时备份并部署当前目标的三个 Mod，核对精确产物哈希；分阶段提交，附注版本标签记录验证边界。

## 交付边界

- 两版结果分别记录，任一失败不宣称双版本完成；最终始终标记“待用户 GUI 验收”。
- 不发布工坊，不复制游戏或框架 DLL 到主 Mod，不新增原版存档跨版本降级转换。
- 本机路径、DLL、镜像、日志、下载与构建输出只留在忽略目录。
